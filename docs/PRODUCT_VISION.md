# PRODUCT_VISION

## 핵심 사용자 흐름 (2026-09-16 기준)

```
원본 입력 (텍스트 / URL / 유튜브 자막)
  → AI가 완성도 높은 칼럼 작성 (구조화된 형태: 제목·부제·도입·소제목별 섹션·핵심 포인트·결론·태그)
  → Notion에 구조화해서 업로드 (heading/paragraph/bullet/callout으로 구분)
  → 사용자가 Notion에서 제목·본문·이미지 등을 최종 수정
  → 사용자가 네이버 블로그 등에 직접 발행
```

Notion 업로드가 이 파이프라인의 **기본 CTA**다. "예쁜 공개 페이지로 발행"은 현재
우선순위에서 제외됐고, 기본 화면 흐름에는 노출하지 않는다 (레거시 기능으로 접어
둠). 이유와 예외는 `docs/OWNER_CONTEXT.md` 참고.

## 글 품질 기준

1. 원문의 핵심 사실과 논지를 정확하게 보존한다.
2. 원문의 문장과 문단 구조를 그대로 베끼지 않는다 — 새 문장으로 재구성.
3. 글 전체에 하나의 분명한 중심 메시지가 있다.
4. 첫 문단에서 독자가 왜 이 글을 읽어야 하는지 자연스럽게 보여준다.
5. 소제목과 문단 순서가 논리적으로 이어진다.
6. 추상적인 설명만 하지 않고, 원문에 있는 구체적인 조건·수치·상황을 살린다.
7. 같은 내용을 표현만 바꿔 반복하지 않는다.
8. "중요합니다", "살펴보겠습니다", "도움이 됩니다" 같은 상투적인 문장을 남발하지
   않는다.
9. AI가 쓴 글처럼 지나치게 정리된 말투나 기계적인 나열을 피한다.
10. 결론에서 앞 내용을 단순 반복하지 않고, 독자가 판단하거나 행동할 기준을
    정리한다.
11. 검색 키워드를 억지로 반복하지 않는다.
12. 선정적 제목, 허위 긴급성, 결과·수익 보장 표현을 쓰지 않는다.
13. 사용자가 입력한 글쓰기 스타일 가이드와 톤을 최우선으로 적용한다 (다만 12번
    규칙은 문체와 무관하게 항상 유지).
14. 법률·금융뿐 아니라 향후 교육·입시 콘텐츠에도 쓸 수 있도록, 특정 분야의
    말투를 생성 함수에 하드코딩하지 않는다. 분야별 안전 규칙(예: 법률·금융의
    "결과 보장 금지")과 사용자의 문체 설정은 프롬프트에서 구분해서 다룬다.

## 원문 충실성 (분야 불문 공통 규칙)

- 원문에 없는 통계·금액·기간·날짜·사례·판례·기관명·인용문을 만들지 않는다.
- 원문에서 확실하지 않은 내용을 사실처럼 단정하지 않는다.
- 원문의 주장과 사실을 구분한다.
- 원문의 중요한 예외 조건·단서를 빼서 의미를 바꾸지 않는다.
- 조건에 따라 결론이 달라지는 내용(법률·금융·교육 공통)을 과도하게 일반화하지
  않는다.
- 원문에 근거가 부족하면 분량을 부풀리지 말고 짧게 유지한다.
- 외부 지식·웹 검색 결과를 섞지 않는다 (별도 기능 요청이 있을 때만).

## 출력 데이터 구조

`title / subtitle / introduction / sections[heading, paragraphs, bullets?, ordered?, callout?, quote?]
/ keyPoints / conclusion / tags` — 자세한 스키마와 파싱 방어 처리는
`docs/tasks/column-notion-quality.md` 4절 참고. AI는 이 구조를 태그 구분자
(###) 형식으로만 출력하고(JSON은 한국어 자유 서술문에서 이스케이프가 자주
깨져서 쓰지 않음), BlockNote 내부 포맷이나 Notion API 원본 JSON을 직접 만들지
않는다 — 코드가 검증 후 변환한다.
