# OWNER_CONTEXT

사용자는 개인회생·형사사건 등을 다루는 법률사무소의 마케팅 콘텐츠를 직접
운영한다. 원본 칼럼(또는 유튜브 영상, URL)을 받아서 AI로 재작성한 칼럼, 카드뉴스,
릴스 대본을 만들어 네이버 블로그·인스타그램 등에 발행하는 데 이 도구를 쓴다.

## 2026-09-16 제품 방향 변경

- **당분간 "Apple 스타일 예쁜 공개 페이지"(`/c/:slug`) 기능은 핵심 제품 방향에서
  제외한다.** 자체 편집기(BlockNote/Tiptap 등)를 계속 확장하는 것도 현재 범위가
  아니다.
- **칼럼의 기본 발행 경로는 Notion이다.** AI가 칼럼을 생성하면 Notion에 구조화된
  페이지로 업로드하고, 사용자는 Notion 안에서 제목·본문·이미지를 최종 수정한 뒤
  네이버 블로그 등에 직접 발행한다.
- 기존에 이미 발행된 `/c/:slug` 공개 링크와 그 저장 데이터는 깨뜨리지 않는다.
  관련 백엔드 코드(`api/publish-page.js`, `api/p/[slug].js`,
  `lib/renderColumnPage.js`, `lib/notionToHtml.js`)도 무리하게 삭제하지 않는다.
  다만 칼럼 제작 화면에서 "예쁜 페이지로 발행" 버튼은 기본 흐름에서 숨기거나
  현재 사용하지 않는 기능임을 명확히 표시한다.
- 지금 가장 중요한 개선 목표는 **"칼럼 글 자체의 품질"** — 사람 편집자가 원문을
  읽고 재구성한 것처럼 보이면서도 원문에 없는 사실·수치·판례·인용을 만들지 않는
  것. 자세한 기준은 `docs/PRODUCT_VISION.md`, 구현 명세는
  `docs/tasks/column-notion-quality.md` 참고.

## 왜 이렇게 바꿨는지

- 공개 페이지 편집기(Tiptap → BlockNote로 두 번 교체)에 이미 많은 시간이 들어갔지만,
  실제 발행은 네이버 블로그 등 외부 플랫폼에서 이뤄지므로 자체 공개 페이지의
  효용이 낮다고 판단.
- Notion은 사용자가 이미 익숙한 편집 도구이고, 팀원과의 공유·리뷰도 Notion에서
  이뤄지는 경우가 많아 "최종 수정 장소"로 더 적합하다.
- AI 결과의 "글 품질"이 구조(소제목/목록 유무)보다 더 근본적인 문제였고, Notion
  업로드가 평문 덩어리로만 올라가는 것도 결국 AI 출력이 구조화돼 있지 않아서였다.
